## 1. Table Schema — `audit_logs`

| Column | Type (SQLAlchemy) | SQL Type | Nullable | Default | Notes |
|---|---|---|---|---|---|
| `id` | `String(36)` | `VARCHAR(36)` | No (PK) | — | Generated by `event_generator.generate_audit_id()` as `f"aud-{uuid.uuid4().hex[:8]}"` (12 characters). The AI auditor interview writer in `audits.py` uses the same pattern. |
| `session_id` | `String(36)`, `ForeignKey("game_sessions.id", ondelete="CASCADE")` | `VARCHAR(36)` | No | — | Foreign key linking to the active or archived (quarantined) `game_sessions.id`. Rows are removed with their session by the ORM cascade on a session reset (SQLite's `foreign_keys` pragma is off). |
| `timestamp` | `DateTime` | `DATETIME` | Yes* | `datetime.utcnow` | Persisted UTC insertion time (naive datetime, set by the column default). In-memory ledger entries (`TICK_BROADCAST.recent_audits`, `GET /api/audits`) carry a separate ISO-8601 timestamp with `+00:00` created when the event is built. |
| `tick` | `Integer` | `INTEGER` | No | — | Logical clock tick when the event was committed. Set to `0` for post-hoc rows written by the API layer (`AI_AUDITOR_INTERVIEW_TURN`). |
| `event_type` | `String(50)` | `VARCHAR(50)` | No | — | Closed set of 38 event types cataloged in § 2 (closed by convention in code; there is no database `CHECK` constraint). |
| `actor` | `String(50)` | `VARCHAR(50)` | No | — | Subsystem actor, one of 9 values: `AUDIT_SYSTEM`, `VP_OF_INFRA`, `AUTOMATED_MONITOR`, `BOARD_OF_DIRECTORS`, `PLATFORM`, `PLATFORM_TEAM`, `EXTERNAL_MONITOR`, `CI_PIPELINE`, `BORDER_FIREWALL`. |
| `details_json` | `Text` | `TEXT` | No | — | Serialized JSON dictionary carrying event payload attributes. Financial events additionally carry `amount` (signed cash movement) and `balance_after`. |
| `compliance_flag` | `Boolean` | `BOOLEAN` | No | `True` | `True` indicates compliant operation; `False` indicates a regulatory, policy, or financial control breach or an adverse event. |

\* Permitted `NULL` in ORM declaration, populated by column default on insert.

No secondary index is declared on `audit_logs`; only the primary key is indexed.

## 2. Complete Authoritative Event Type Catalog (38 Event Types)

The table below catalogs every event type emitted by the codebase. "Incident ID Ref" states whether the payload carries an `incident_id` key (the dossier in Document 05 only reads such rows).

| Event Type | Trigger Origin | Default Actor | Compliance Flag | Financial Impact | Incident ID Ref | Purpose & Description |
|---|---|---|---|---|---|---|
| `INCIDENT_RAISED` | Failure hazard roll, scenario/chaos injection, materialized pre-alert, or the tutorial incident | `AUTOMATED_MONITOR` | `True` | None directly (per-tick surcharge accrues without audit rows) | Yes | Failure detected; alert raised. |
| `INCIDENT_ACKNOWLEDGED` | Player acknowledges alert | `VP_OF_INFRA` | `True` | Halts unattended fine clock | Yes | Freezes MTTA clock. |
| `INVESTIGATION_STARTED` | First triage submission on an incident | `VP_OF_INFRA` | `True` | None | Yes | Records triage attempt initiation. |
| `ROOT_CAUSE_IDENTIFIED` | Correct root-cause match | `VP_OF_INFRA` | `True` | Forward runbook discount | Yes | Confirms diagnosis; unlocks discount. |
| `RUNBOOK_EXECUTED` | Mitigation runbook executed | `VP_OF_INFRA` | `True` | Direct deduction (`cost`) | Yes (null when no open incident matched) | Heals or only partially mitigates the service; tech debt delta. |
| `PROACTIVE_REFACTOR_CYCLE` | Every 20th consecutive incident-free tick while TDI > 0 | `PLATFORM_TEAM` | `True` | None (-1 TDI) | No | Ambient technical debt relief. |
| `UNATTENDED_ALERT_VIOLATION` | Effective MTTA of an `active` incident $\ge 12$ ticks (each tick) | `AUDIT_SYSTEM` | `False` | \$4,500 fine per tick | Yes | Regulatory sanction for alert negligence. |
| `SLA_BREACH_EMERGENCY_SANCTION` | Rolling window SLA < 99.00% (tick > 24); once per breach episode | `AUDIT_SYSTEM` | `False` | None (flips status to `breached`; no money is debited) | No | Regulatory breach emergency warning. |
| `FEATURE_FREEZE_ENGAGED` | Error budget exhausted ($\le 0$) | `AUDIT_SYSTEM` | `False` | Blocks risky actions | No | Freezes non-remedial change management. |
| `FEATURE_FREEZE_LIFTED` | Error budget replenished | `AUDIT_SYSTEM` | `True` | None | No | Restores full CAB change velocity. |
| `DILEMMA_OFFERED` | Periodic CAB trigger (every 40-60 ticks after the previous one) | `BOARD_OF_DIRECTORS` | `True` | None | No | Offers governance choice to player. |
| `DILEMMA_RESOLVED` | Player selects option, or the 30-tick window expires | `VP_OF_INFRA` (player) / `BOARD_OF_DIRECTORS` (auto-resolved) | Derived (`choice["tech_debt_delta"] <= 5`) | Direct delta (`budget_delta`) | No | Applies decision consequences and reputation delta. |
| `ELEVATED_RISK_WINDOW_OPENED` | A CAB choice carries a temporary hazard window | `AUDIT_SYSTEM` | `False` | None | No | Elevates failure risk window temporarily. |
| `ENGINEER_HIRED` | Engineer hired to roster | `VP_OF_INFRA` | `True` | Direct deduction (\$15,000) | No | Recruits on-call engineer to roster. |
| `SHIFT_ROTATED` | Engineer toggled on-duty/resting | `VP_OF_INFRA` | `True` | None | No | Rotates engineer on-call shift status. |
| `UPGRADE_PURCHASED` | Tech tree upgrade bought | `VP_OF_INFRA` | `True` | Direct deduction (`cost`) | No | Unlocks systemic operational capability. |
| `INFRASTRUCTURE_NODE_PLACED` | Build mode node placed | `VP_OF_INFRA` | `True` | Direct deduction (`cost`) | No | Deploys infrastructure hardware. |
| `INFRASTRUCTURE_NODE_REMOVED` | Build mode node deleted | `VP_OF_INFRA` | `True` | None (no refund) | No | Decommissions placed infrastructure node. |
| `AI_AUDITOR_INTERVIEW_TURN` | Defense turn completed (`.../interview`) | `AUDIT_SYSTEM` | `False` if verdict is NON_COMPLIANT, else `True` | Proposed only (no cash movement) | Yes | Records post-mortem Q&A turn (`tick = 0`). |
| `AI_AUDITOR_VERDICT_APPLIED` | Player applies interview verdict (`.../interview/apply-verdict`) | `AUDIT_SYSTEM` | `False` if verdict is NON_COMPLIANT, else `True` | Clamped fine/credit | Yes | Applies backend-verified adjustment. |
| `CHAOS_STRIKE` | Chaos Engineering Drill injects a random fault (20% per tick) | `AUTOMATED_MONITOR` | `True` | None | No (`service_id` only; the paired `INCIDENT_RAISED` carries the id) | Chaos engineering failure injection. |
| `PATIENT_ZERO_IDENTIFIED` | Ransomware scenario starts | `AUTOMATED_MONITOR` | `False` | None | No (`service_id`) | Initial perimeter intrusion entry point. |
| `DDOS_ATTACK_DETECTED` | DDoS Global scenario starts | `BORDER_FIREWALL` | `True` | None | No | Volumetric attack detected at the perimeter (`attack_type`, `target_service`, `estimated_gbps`). |
| `DEPLOYMENT_REGRESSION_DETECTED` | Deployment Rollback scenario starts | `CI_PIPELINE` | `True` | None | No | Bad deploy identified (`commit_sha`, `affected_services`, `regression_type`, `deploy_environment`); `srv-auth` and `srv-search` start degraded. |
| `SECOND_REGRESSION_WAVE` | Deployment Rollback scenario, scenario tick 20, when no affected service has been triaged | `AUTOMATED_MONITOR` | `True` | None | No | Memory-pool exhaustion escalates error rates on both affected services. |
| `THIRD_PARTY_PROVIDER_OUTAGE` | Third-Party Outage scenario starts | `EXTERNAL_MONITOR` | `False` | None | No | Upstream vendor outage begins (adverse event). |
| `THIRD_PARTY_PROVIDER_RECOVERED` | Provider recovers (lottery from scenario tick 15, or the deadline tick 40) | `EXTERNAL_MONITOR` | `True` | None | No | Vendor back online; ends the run and triggers scoring. |
| `SCENARIO_CONCLUDED` | Scenario reaches its own end condition | `AUDIT_SYSTEM` | `outcome["compliant"]` | None | No | Records scenario outcome and victory status. |
| `MONTHLY_AUDIT_CYCLE_SURVIVED` | 720 ticks survived in sandbox with rolling SLA $\ge 99.00\%$ | `AUDIT_SYSTEM` | `True` | None | No | Successful monthly compliance survival. |
| `BANKRUPTCY_LIQUIDATION` | Budget reaches \$0.00 | `BOARD_OF_DIRECTORS` | `False` | Terminal halt | No | Financial liquidation and session end. |
| `SYSTEM_RESTORED` | Session restored from snapshot | `PLATFORM` | `True` | None | No | Crash recovery rehydration completed. |
| `SNAPSHOT_VERSION_MISMATCH` | Incompatible snapshot found | `PLATFORM` | `False` | None | No | Triggers isolation quarantine. |
| `ACHIEVEMENT_UNLOCKED` | Career milestone achieved | `AUDIT_SYSTEM` | `True` | Prestige points awarded | No | Records permanent career achievement. |
| `COSMETIC_UNLOCKED` | Player spends prestige on an office cosmetic | `VP_OF_INFRA` | `True` | Prestige points deducted | No | Unlocks visual office customization. |
| `SESSION_ARCHIVED_AND_PURGED` | `POST /api/session/reset` on a session that had a ledger or had ticked, written into the **new** session's ledger right after the reset | `PLATFORM` | `True` | None | No | Closes the reset gap: the purged session's ledger is summarized and checksummed into `archived_audit_ledgers` first (`archive_id`, `purged_session_id`, `final_tick`, `final_status`, `final_budget`, `event_count`, `incident_count`, `events_by_type`, `ledger_checksum`). | `TRAFFIC_THROTTLED` | Player fires the emergency traffic throttle on a failing service (`POST /api/services/{id}/throttle`) | `VP_OF_INFRA` | `True` | Direct deduction (\$600) | Yes | Sheds ~50% of the service's requests for a short window; does **not** resolve the incident (`service_id`, `incident_id`, `cost`, `window_ticks`). |

## 4. Query & Access Patterns

The compliance ledger is queried via SQLAlchemy through several access paths (none backed by a secondary index; the table is small per session and bounded by the single-session design):
1. **Dossier Compilation (`_build_incident_dossier`):** Selects `audit_logs` rows of the incident's `session_id` whose `event_type` is one of `RUNBOOK_EXECUTED`, `UNATTENDED_ALERT_VIOLATION`, `ROOT_CAUSE_IDENTIFIED`, `INVESTIGATION_STARTED`, `AI_AUDITOR_VERDICT_APPLIED` and keeps those whose `details_json.incident_id` matches exactly (checked in Python). A second query selects the session-wide context event types inside the incident's tick window (`tick >= created_tick` and `tick <= resolved_tick`, or `created_tick + 50` while open).
2. **Idempotency Verification (`_verdict_already_applied`):** Queries for `event_type == 'AI_AUDITOR_VERDICT_APPLIED'` and checks in Python whether `details_json` contains the target `incident_id` (note: this query is not filtered by `session_id`).
3. **Session Restore Rehydration:** Queries the most recent 1,000 entries ordered by `tick DESC` to populate runtime memory mirrors and reconstruct the runtime financial ledger.
