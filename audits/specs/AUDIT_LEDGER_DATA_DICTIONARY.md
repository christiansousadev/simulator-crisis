## 1. Table Schema — `audit_logs`

| Column | Type (SQLAlchemy) | SQL Type | Nullable | Default | Notes |
|---|---|---|---|---|---|
| `id` | `String(36)` | `VARCHAR(36)` | No (PK) | — | Generated by `event_generator.generate_audit_id()` as `f"aud-{uuid.uuid4().hex[:8]}"` (12 characters). |
| `session_id` | `String(36)`, `ForeignKey("game_sessions.id", ondelete="CASCADE")` | `VARCHAR(36)` | No | — | Foreign key linking to the active or archived `game_sessions.id`. |
| `timestamp` | `DateTime` | `DATETIME` | Yes* | `datetime.utcnow` | Persisted UTC execution timestamp. |
| `tick` | `Integer` | `INTEGER` | No | — | Authoritative logical clock tick when event was committed. Set to `0` for post-hoc actions (`AI_AUDITOR_INTERVIEW_TURN`). |
| `event_type` | `String(50)` | `VARCHAR(50)` | No | — | Closed set of 29 authoritative event types cataloged in § 2. |
| `actor` | `String(50)` | `VARCHAR(50)` | No | — | Subsystem actor (`AUTOMATED_MONITOR`, `VP_OF_INFRA`, `PLATFORM_TEAM`, `BOARD_OF_DIRECTORS`, `AUDIT_SYSTEM`, `PLATFORM`). |
| `details_json` | `Text` | `TEXT` | No | — | Serialized JSON dictionary carrying event payload attributes. |
| `compliance_flag` | `Boolean` | `BOOLEAN` | No | `True` | `True` indicates compliant operation; `False` indicates a regulatory, policy, or financial control breach. |

\* Permitted `NULL` in ORM declaration, populated by column default on insert.

## 2. Complete Authoritative Event Type Catalog (29 Event Types)

|---|---|---|---|---|---|---|
| `INCIDENT_RAISED` | Stochastic failure roll | `AUTOMATED_MONITOR` | `True` | Indirect (passive burn) | Yes | Failure detected; alert raised. |
| `INCIDENT_ACKNOWLEDGED` | Player acknowledges alert | `VP_OF_INFRA` | `True` | Halts unattended fine clock | Yes | Freezes MTTA clock. |
| `INVESTIGATION_STARTED` | First triage submission | `VP_OF_INFRA` | `True` | None | Yes | Records triage attempt initiation. |
| `ROOT_CAUSE_IDENTIFIED` | Correct root-cause match | `VP_OF_INFRA` | `True` | Forward runbook discount | Yes | Confirms diagnosis; unlocks discount. |
| `RUNBOOK_EXECUTED` | Mitigation runbook executed | `VP_OF_INFRA` | `True` | Direct deduction (`cost`) | Yes | Heals or degrades service; tech debt delta. |
| `PROACTIVE_REFACTOR_CYCLE` | 20 quiet ticks elapsed | `PLATFORM_TEAM` | `True` | None (-1 TDI) | No | Ambient technical debt relief. |
| `UNATTENDED_ALERT_VIOLATION` | Active MTTA $\ge 12$ ticks | `AUDIT_SYSTEM` | `False` | \$4,500 fine per tick | Yes | Regulatory sanction for alert negligence. |
| `SLA_BREACH_EMERGENCY_SANCTION` | Rolling window SLA < 99.00% (tick > 24) | `AUDIT_SYSTEM` | `False` | None (signals non-compliance) | No | Regulatory breach emergency warning. |

| `UPGRADE_PURCHASED` | Tech tree upgrade bought | `VP_OF_INFRA` | `True` | Direct deduction (`cost`) | No | Unlocks systemic operational capability. |
| `INFRASTRUCTURE_NODE_PLACED` | Build mode node placed | `VP_OF_INFRA` | `True` | Direct deduction (`cost`) | No | Deploys spatial infrastructure hardware. |
| `INFRASTRUCTURE_NODE_REMOVED` | Build mode node deleted | `VP_OF_INFRA` | `True` | None (no refund) | No | Decommissions placed infrastructure node. |
| `AI_AUDITOR_INTERVIEW_TURN` | Defense turn completed | `AUDIT_SYSTEM` | False if NON_COMPLIANT | Proposed only | Yes | Records post-mortem Q&A turn. |
| `AI_AUDITOR_VERDICT_APPLIED` | Player applies interview verdict | `AUDIT_SYSTEM` | False if NON_COMPLIANT | Clamped fine/credit | Yes | Applies backend-verified adjustment. |
| `CHAOS_STRIKE` | Drill injects random fault | `AUTOMATED_MONITOR` | `True` | None | Yes | Chaos engineering failure injection. |
| `PATIENT_ZERO_IDENTIFIED` | Ransomware scenario starts | `AUTOMATED_MONITOR` | `False` | None | Yes | Initial perimeter intrusion entry point. |

| `MONTHLY_AUDIT_CYCLE_SURVIVED` | 720 ticks survived in sandbox | `AUDIT_SYSTEM` | `True` | None | No | Successful monthly compliance survival. |
| `BANKRUPTCY_LIQUIDATION` | Budget reaches \$0.00 | `BOARD_OF_DIRECTORS` | `False` | Terminal halt | No | Financial liquidation and session end. |
| `SYSTEM_RESTORED` | Session restored from snapshot | `PLATFORM` | `True` | None | No | Crash recovery rehydration completed. |
| `SNAPSHOT_VERSION_MISMATCH` | Incompatible snapshot found | `PLATFORM` | `False` | None | No | Triggers isolation quarantine. |
| `ACHIEVEMENT_UNLOCKED` | Career milestone achieved | `AUDIT_SYSTEM` | `True` | Prestige points awarded | No | Records permanent career achievement. |
| `COSMETIC_UNLOCKED` | Office cosmetic purchased | `VP_OF_INFRA` | `True` | Prestige points deducted | No | Unlocks visual office customization. |

## 4. Query & Indexing Patterns

The compliance ledger is queried via SQLAlchemy through several indexed access paths:
1. **Dossier Compilation (`_build_incident_dossier`):** Queries `audit_logs` filtering by `session_id` and the incident tick range (`tick >= created_tick` and `tick <= resolved_tick`).
2. **Idempotency Verification (`_verdict_already_applied`):** Queries for `event_type == 'AI_AUDITOR_VERDICT_APPLIED'` where `details_json` contains the target `incident_id`.
3. **Session Restore Rehydration:** Queries the most recent 1,000 entries ordered by `tick DESC` to populate runtime memory mirrors and reconstruct the runtime financial ledger.
